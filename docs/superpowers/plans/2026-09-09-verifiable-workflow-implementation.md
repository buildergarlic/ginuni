# 검증 가능한 AI 워크플로우 구현

설계 근거: `docs/diagrams/2026-08-31-verifiable-ai-workflow.md` 및 작가 중심 업그레이드 설계 §14.

## 공통 제약

- 화면해설은 작가가 직접 작성한다. 음성 인식과 선택적 교정은 대사 초안용이다.
- 편집은 승인이 아니다. 명시적 행 승인, 수정 시 승인 해제, 원문 보존과 복구가 필요하다.
- 프로젝트 자료는 로컬에 둔다. 외부 음성 분석/교정은 각각 동의를 받아 제한된 요청만 전송한다.
- 자동 검사는 정확도를 보증하지 않는다. 정답 평가와 작업 중 검사를 분리한다.
- 기존 프로젝트와 HWPX/SRT 기능을 보존하며 직접-main 개발 정책을 따른다.

## Task 1: 검수·영속성

`src/shared/workflow.ts`, `src/main/services/project-store.ts`, 관련 테스트를 담당한다. types.ts에 확정된 계약에 맞춰 마이그레이션, 검수 오류 수집, 결과 검사, 승인, 감사 이벤트, revision 충돌 방지, 직렬 트랜잭션, 최근 10개 JSON 스냅샷과 복구를 구현한다. 원본 segments/runs는 일반 행 편집과 복구로 삭제하지 않는다. 편집 전후를 로컬에 기록한다. 잘못된 IPC 입력은 저장 전에 거부한다.

## Task 2: 작가 화면

`App.tsx`, `styles.css`와 새 renderer 컴포넌트/테스트를 담당한다. 3단계 안내, 쉬운 한국어, 고급 옵션 접기, 권리/외부 전송 동의, 검수 목록과 다음 항목 이동, 명시적 승인, 원본 구간 보기, 교정 전후 적용·거절, 이전 상태 복구, 기록 보기/저장을 연결한다. 저장 완료 후에 승인·교정·복구 요청을 실행하고 편집 중 충돌/유실을 방지한다. 기존 재생·분할·병합·내보내기와 키보드 사용을 유지한다.

## Task 3: 선택적 AI 교정

`src/main/services/correction.ts` 및 관련 테스트를 담당한다. 기존 설치 SDK와 저장 키를 이용한 OpenAI 텍스트 교정 제안만 생성한다. JSON 스키마로 행 ID와 before/after/reason을 검사한다. 입력은 명령이 아닌 자료다. 선택한 대사만 최대 20행/12,000자, API 재시도 없음, 60초 제한, 출력 토큰 제한. 해설 행·시간·화자·sourceSegmentIds는 변경하지 않는다. 원문과 현재 내용 불일치 제안은 적용 불가. 네트워크 없이 테스트한다.

## Task 4: 실행 연결·출력·개발자 평가

main/preload 연결, 분석 전 동의와 입력 해시, 실패 시 기존 대본 보존, 성공 전 형식/시간 검사, 내보내기 오류 차단과 미승인 경고, HWPX/SRT 산출물 구조 검사와 해시 기록을 구현한다. 정답 기반 로컬 평가 도구는 CER/WER/고유명사 재현율 및 처리/작가 검수 시간·비용 자료를 계산한다. DER/SubER는 정답/공식 도구 결과가 있을 때만 수록하고 미측정값을 0으로 표시하지 않는다. 실사용 파일 자동 업로드나 자동 모델 교체는 구현하지 않는다.

## 검증

기능별 실패 테스트 → 구현 → 관련 테스트. 마지막 `npm run verify`, 출력 QA, 가능한 범위의 Electron UI 확인, 독립 코드 검토. 실 API 호출과 방송 자료/실제 작가 사용성 시험은 별도 실측이 필요하며 실행했다고 주장하지 않는다.
