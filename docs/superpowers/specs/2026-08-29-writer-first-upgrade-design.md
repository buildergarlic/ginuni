# GiNuNi 화면해설작가 중심 업그레이드 설계

> 작성일: 2026-08-29
>
> 기준 버전: `v0.5.0-beta.7`
>
> 대상 사용자: 시각장애인을 위한 화면해설 방송 대본을 작성하는 화면해설작가
>
> 관련 자료: 2026-08-29 OSSAI 멘토 피드백 메모 3장

## 1. 결정 요약

GiNuNi의 다음 업그레이드는 특정 AI 모델 하나로 교체하는 사업이 아니다. **작가는 세 단계만 이해하면 작업할 수 있고, 개발자는 뒤에서 음성 인식·화자 분리·후처리 모델을 독립적으로 비교할 수 있는 구조**를 만든다.

기본 방향은 다음과 같다.

1. 로컬 처리를 기본값으로 유지한다.
2. 일반 화면에서 모델명, 런타임명, 파라미터를 숨긴다.
3. 작업 흐름을 `영상 가져오기 → 자동 대사 만들기 → 확인하고 저장하기`로 고정한다.
4. 모든 AI 결과는 수정 가능한 초안이며, 원문을 자동으로 덮어쓰지 않는다.
5. 작가가 확인해야 할 구간을 시스템이 먼저 모아 보여준다.
6. 여러 전사·화자 분리 방식을 동일한 평가 자료와 지표로 비교한다.
7. 작가의 수정 결과는 기본적으로 해당 PC에만 저장하며, 명시적 동의 없이 외부 학습에 사용하지 않는다.

## 2. 멘토 메모 반영 범위

첨부 메모는 제품 요구사항을 직접 지시하는 문서가 아니라 설계 참고자료로 해석했다. 필기에서 비교적 명확하게 확인되는 제안을 다음과 같이 제품 요구로 정리했다.

| 메모 주제 | 제품 반영 결정 |
| --- | --- |
| Whisper와 VAD 전처리 | 현재 Silero VAD와 Whisper 처리를 평가 가능한 독립 단계로 유지한다. |
| 화자 분리 및 파라미터 튜닝 | 화자 분리를 STT와 분리해 평가하고, 배경음·겹침 발화·화자 수별 기준값을 관리한다. |
| SRT·타임스탬프·화자 정보 | 전사 공급자가 달라도 공통 세그먼트 형식으로 정규화하고 HWPX/SRT까지 보존한다. |
| OpenAI·Gemini 등 모델 비교 | 제품 화면에 모델을 바로 노출하지 않고 개발용 평가 도구에서 먼저 비교한다. |
| LLM 수정과 템플릿 | 맞춤법·띄어쓰기·고유명사는 제안으로만 제공하고, 승인된 내용만 대본에 반영한다. |
| AI Hub 공개 데이터 | 데이터별 이용 조건과 저작권을 확인한 자료만 평가 또는 학습에 사용한다. |
| Human-in-the-loop | 작가의 승인·수정 결과로 로컬 용어 사전과 평가 정답을 개선한다. |
| WER·SubER·hotword rate | 한국어 CER/WER, DER, 화자 포함 WER, SubER, 고유명사 재현율을 자동 산출한다. |

메모의 `tcwer`로 보이는 표기는 판독이 불확실하다. 본 설계에서는 같은 목적에 맞는 표준 지표인 화자 포함 WER(cpWER 또는 SA-WER)를 사용하며, 향후 멘토에게 정확한 용어를 확인해 명칭만 교정할 수 있다.

## 3. 현재 시스템 기준선

현재 버전은 다음 기능을 이미 제공한다.

- 로컬 `whisper.cpp` 전사
- 로컬 `whisper.cpp + sherpa-onnx` 화자 분리 실험 모드
- OpenAI `gpt-4o-transcribe-diarize` 전사
- 영상과 표를 함께 보는 검수 화면
- 행 분할·병합·추가·삭제와 화자명 일괄 변경
- 시간 겹침 및 빈 내용 검사
- 자동 저장과 HWPX/SRT 버전 증가 내보내기

보존해야 할 강점은 로컬 우선 처리, 실패 시 기존 대사를 보존하는 안전한 폴백, 원본 파일 비복사, HWPX 호환성이다.

현재 개선이 필요한 부분은 다음과 같다.

- 어떤 행이 실제로 검수 완료됐는지 명확하지 않다. 현재는 행을 한 번 수정하는 것만으로 `reviewed: true`가 된다.
- 화자 분리와 전사 품질을 수치로 비교하는 평가 체계가 없다.
- 작가는 오류 가능성이 높은 구간을 직접 찾아야 한다.
- 모델명과 실험 설정이 일반 사용자에게 노출될 가능성이 있다.
- 고유명사와 반복 교정 내용을 다음 작업에서 재사용할 수 없다.
- AI 교정 제안의 원문 비교·개별 승인·거부 기록이 없다.
- 프로젝트가 손상되거나 잘못 편집된 경우 이전 시점으로 복원하는 명시적 기능이 없다.

## 4. 제품 원칙

### 4.1 작가의 작업 언어를 사용한다

일반 화면에서는 `sherpa-onnx`, `diarization`, `VAD`, `chunking` 같은 용어를 사용하지 않는다. 다음과 같이 작업 결과와 비용·개인정보 영향만 설명한다.

- `내 PC에서 분석` — 음성을 외부로 보내지 않음
- `정확도 우선 분석` — 인터넷과 API 키가 필요하며 비용이 발생할 수 있음
- `화자 수를 아시나요?` — `모르겠어요(권장)`, `2명`부터 `10명`

모델과 파라미터는 `고급 설정`에서만 확인한다.

### 4.2 한 화면에서 한 가지 결정을 요청한다

새 프로젝트 화면에서는 입력 선택과 분석 방식만 결정한다. 검수 화면에서는 현재 구간의 대사·화자·시간만 확인한다. 내보내기 화면에서는 오류와 저장 형식만 확인한다.

### 4.3 숨은 조작을 핵심 경로에 두지 않는다

행 우클릭이나 기억해야 하는 단축키 없이도 모든 핵심 작업을 버튼으로 수행할 수 있어야 한다. 단축키는 숙련자를 위한 보조 수단으로 제공한다.

### 4.4 AI보다 작가의 판단이 우선한다

- AI 수정은 제안 상태로 생성한다.
- 원문, 제안, 변경된 부분을 동시에 확인할 수 있어야 한다.
- `적용`, `거부`, `모두 나중에 확인` 중 하나를 작가가 선택한다.
- 승인 전에는 HWPX/SRT 내용이 바뀌지 않는다.
- 원음에 없는 대사가 추가됐을 가능성이 있는 제안은 자동 차단한다.

### 4.5 실수는 복구할 수 있어야 한다

- 자동 저장 상태를 일반 문장으로 표시한다.
- 중요한 구조 변경 전 스냅샷을 만든다.
- 최근 스냅샷에서 두 번의 클릭 이내로 복원할 수 있어야 한다.
- 내보내기는 기존 파일을 덮어쓰지 않는 현재 정책을 유지한다.

## 5. 목표 사용자 흐름

### 5.1 시작 화면

첫 화면의 주요 동작은 세 개로 제한한다.

1. `새 대본 만들기`
2. `최근 작업 이어서 하기`
3. `처음 사용하는 방법`

새 대본 만들기는 다음 순서로 진행한다.

1. 영상 파일 또는 사용 권한이 있는 유튜브 링크 선택
2. 분석 방식 선택
3. 선택 내용을 한 문장으로 확인
4. `자동 대사 만들기` 실행

### 5.2 분석 진행 화면

단계명과 남은 작업을 작가 언어로 표시한다.

- 영상 확인 중
- 음성 준비 중
- 대사 받아쓰는 중
- 말한 사람 구분 중
- 검수용 대본 만드는 중

실패할 경우 오류 코드보다 먼저 `무엇이 완료됐는지`, `작업을 계속할 수 있는지`, `눌러야 할 버튼`을 보여준다.

### 5.3 검수 화면

기본 레이아웃은 세 영역으로 구성한다.

- 왼쪽: 영상과 재생 제어
- 가운데: 현재 선택한 한 구간의 큰 편집기
- 오른쪽: 확인할 구간 목록과 전체 진행률

검수 상태는 다음 세 값으로 분리한다.

- `미확인`: 아직 작가가 확인하지 않음
- `확인 필요`: 시간 겹침, 빈 내용, 화자 불확실, AI 제안 등 문제가 있음
- `확인 완료`: 작가가 명시적으로 완료 처리함

행을 수정했다는 이유만으로 확인 완료가 되지 않는다.

### 5.4 확인할 구간 모아보기

다음 조건을 검수 이슈로 만든다.

- 종료 시간이 시작 시간보다 빠르거나 같음
- 이전 행과 시간이 겹침
- 내용이 비어 있음
- 화자 분리 결과가 없거나 동률임
- 겹침 발화가 감지됨
- 고유명사 후보가 용어 사전과 다름
- AI 수정 제안이 대기 중임

작가는 `다음 확인 필요 구간` 버튼으로 문제 구간만 순서대로 검수할 수 있다.

### 5.5 내보내기

내보내기 전 요약은 다음 세 가지를 보여준다.

- 확인 완료 행 수
- 아직 확인하지 않은 행 수
- 내보내기를 막는 시간·내용 오류 수

미확인 행은 경고 후 작가가 선택해 내보낼 수 있지만, 시간 겹침과 빈 대사는 수정 전까지 내보내기를 막는다.

## 6. 기술 설계

### 6.1 공통 전사 공급자 구조

현재 `TranscriptionProvider` 경계를 유지하되, 공급자 선택과 사용자용 분석 방식을 분리한다.

- 사용자 설정: `private` 또는 `accuracy`
- 내부 공급자 ID: `local-whisper`, `local-sherpa`, `openai-diarized`, 평가 후보 `gemini-transcribe`
- 공통 출력: 대사, 시작·종료, 화자, 단어 타임스탬프 여부, 공급자 근거 정보

새 공급자는 개발용 평가를 통과하기 전 일반 화면에 노출하지 않는다.

### 6.2 프로젝트 스키마

프로젝트 스키마를 2에서 3으로 올린다.

행은 기존 `reviewed` 불리언 대신 `reviewStatus`를 저장한다. 기존 프로젝트는 다음 규칙으로 변환한다.

- `reviewed: true` → `reviewStatus: approved`
- `reviewed: false` 또는 누락 → `reviewStatus: unreviewed`

프로젝트에는 다음 정보가 추가된다.

- 분석 프로필
- 원본 전사와 공급자 ID
- 검수 이슈
- AI 교정 제안과 승인 상태
- 로컬 용어 사전 참조
- 복원 스냅샷 메타데이터

마이그레이션은 기존 대사·화자·시간·내보내기 기록을 변경하지 않아야 한다.

### 6.3 안전한 교정 제안

교정 서비스는 원문을 직접 저장하지 않고 다음 구조의 제안만 반환한다.

- 대상 행 ID
- 원문
- 제안문
- 변경 이유: 띄어쓰기, 맞춤법, 고유명사, 문장부호
- 신뢰도
- 상태: 대기, 적용, 거부

제안문에 원문과 연결되지 않는 새 어절이 과도하게 포함되면 `확인 필요`로 분류하고 일괄 적용을 금지한다.

### 6.4 로컬 용어 사전

용어 사전은 Windows 사용자 데이터 폴더에 저장한다. 기본값은 로컬 저장이며 외부로 전송하지 않는다.

각 항목은 다음 값을 가진다.

- 올바른 표기
- 잘못 인식되는 표기 목록
- 분류: 인물, 지명, 작품명, 일반 용어
- 마지막 사용 시각

클라우드 전사에서 지원하는 경우 해당 작업의 키워드 힌트로만 전달한다. 관련 없는 모든 용어를 매번 보내지 않는다.

### 6.5 복구

다음 시점에 프로젝트 스냅샷을 만든다.

- 분석 완료 직후
- 행 10개 이상에 영향을 주는 일괄 변경 전
- 화자명 전체 변경 전
- AI 제안 일괄 적용 전
- 내보내기 직전

프로젝트별 최근 10개만 유지하며, 스냅샷에는 프로젝트 JSON만 포함한다. 원본 영상과 전사용 음성을 중복 복사하지 않는다.

## 7. 평가 설계

### 7.1 평가 자료

첫 평가 세트는 사용 권한이 확인된 30개 클립, 합계 2~3시간으로 구성한다.

| 분류 | 최소 수량 | 포함 조건 |
| --- | ---: | --- |
| 조용한 2인 대화 | 6 | 남녀 조합과 말 빠르기 다양화 |
| 배경음악·효과음 | 6 | 대사가 음악보다 작은 구간 포함 |
| 겹침 발화 | 6 | 짧은 맞장구와 긴 동시 발화 포함 |
| 3인 이상 대화 | 6 | 장면 중간 출연자 추가 포함 |
| 고유명사 집중 | 6 | 인물명·지명·외래어 포함 |

각 클립에는 사람이 확인한 대사, 화자, 시작·종료 시간, 고유명사 목록을 기록한다.

AI Hub 자료는 개별 데이터셋의 이용정책과 권리 범위를 확인한 후 평가용으로만 반입한다. 권리가 불명확한 방송 영상·대본·자막은 저장소나 배포 파일에 포함하지 않는다.

### 7.2 자동 지표

- 한국어 문자 오류율(CER)
- 단어 오류율(WER)
- 화자 분리 오류율(DER)
- 화자 포함 WER(cpWER 또는 SA-WER)
- 자막 편집률(SubER)
- 고유명사 정밀도·재현율
- 실시간 배수(RTF)
- 영상 1시간당 API 비용
- 분석 실패율

### 7.3 작가 중심 지표

- 영상 10분당 검수 시간
- 영상 10분당 대사 수정 횟수
- 영상 10분당 화자명 수정 횟수
- 처음 사용하는 작가의 도움 없이 내보내기 완료율
- 작업 중 길을 잃어 되돌아간 횟수
- 자동 저장 및 복원 성공률
- 치명적인 허구 문장 건수

### 7.4 모델 채택 조건

새 모델은 다음 조건을 모두 만족할 때만 기본 또는 권장 옵션이 된다.

1. 전체 평가 세트에서 기존 방식보다 작가의 실제 수정 시간이 15% 이상 감소한다.
2. 고유명사 재현율과 화자 구분 정확도가 기존보다 나빠지지 않는다.
3. 치명적인 허구 문장 사례가 없다.
4. 실패 시 원본 대사 또는 기존 공급자로 안전하게 복귀한다.
5. 비용과 외부 전송 여부가 실행 전에 명확히 표시된다.

## 8. 개인정보·저작권 원칙

- 로컬 분석을 기본값으로 유지한다.
- 클라우드 분석은 작업마다 외부 전송 사실을 명확히 표시한다.
- API 키, 원문 대사, 음성 내용은 로그와 진단 파일에 기록하지 않는다.
- 작가 수정 결과를 서버로 자동 업로드하지 않는다.
- 평가 자료는 권리 근거, 허용 용도, 보관 위치, 삭제일을 매니페스트에 기록한다.
- AI Hub 데이터는 AI Hub 전체에 하나의 포괄 라이선스가 있다고 가정하지 않고 데이터별 조건을 확인한다.
- 실제 방송 대본과 영상은 공개 테스트 픽스처에 포함하지 않는다.

## 9. 접근성과 사용성 완료 조건

- 핵심 기능을 마우스만으로 사용할 수 있다.
- 핵심 기능을 키보드만으로도 사용할 수 있다.
- 주요 버튼의 레이블은 동작과 결과를 함께 설명한다.
- 오류는 색상만으로 구분하지 않는다.
- 기본 글자 크기는 Windows 배율 125%에서 읽기 편해야 하며 검수 글자 크기를 조절할 수 있다.
- 초보 작가가 개발자 도움 없이 `영상 선택 → 분석 → 한 행 수정 → HWPX 저장`을 완료한다.
- 핵심 조작이 우클릭 메뉴에만 존재하지 않는다.
- 현재 저장 상태와 다음에 해야 할 동작을 화면에서 항상 확인할 수 있다.

## 10. 12주 릴리스 로드맵

| 기간 | 릴리스 목표 | 사용자에게 보이는 결과 |
| --- | --- | --- |
| 1주차 | 기준선과 평가 자료 | 기존 버전의 정확도·검수 시간 기준 확보 |
| 2~3주차 | 검수 상태와 쉬운 시작 흐름 | 모델명을 몰라도 새 작업을 시작하고 진행 상태를 이해함 |
| 4~5주차 | 확인 필요 구간과 복구 | 문제 구간만 순서대로 확인하고 이전 상태로 복원 가능 |
| 6~8주차 | 공급자 비교와 평가 자동화 | 개발자가 동일 자료로 로컬·OpenAI·후보 모델을 비교 |
| 9~10주차 | 용어 사전과 안전한 AI 교정 | 고유명사를 재사용하고 수정 전후를 보고 적용 |
| 11주차 | 실제 파일·내보내기 검증 | 실제 분량에서 HWPX/SRT와 한컴오피스 호환성 확인 |
| 12주차 | 화면해설작가 파일럿 | 교육 없이 작업을 끝내고 발견된 문제를 베타에 반영 |

세부 구현 순서, 파일별 변경, 테스트와 커밋 단위는 `docs/superpowers/plans/2026-08-29-writer-first-upgrade.md`에 정의한다.

## 11. 출시 기준

- 파일럿 참여 화면해설작가의 작업 완료율 90% 이상
- 기존 버전 대비 영상 10분당 검수 시간 25% 이상 감소
- 평가 및 파일럿에서 치명적인 허구 문장 0건
- 평가 프로젝트 HWPX/SRT 내보내기 실패 0건
- 모든 AI 교정에 원문 비교, 개별 승인, 거부, 되돌리기 제공
- 스키마 1·2 프로젝트의 대사·화자·시간·내보내기 기록 보존
- `npm run verify` 통과
- 한컴오피스 2022에서 HWPX 복구 경고 없이 열림
