# 외화의 한국어 자막으로 화면해설 대본 시작하기

GiNuNi `0.7.0-beta.2`용 안내입니다. **로컬 영상과 한국어 SRT가 있으면 음성 분석 없이 대사와 시간을 가져와 작업할 수 있습니다.** SRT가 없으면 영상을 보며 첫 행부터 직접 입력합니다. 영상에 입혀진 글자를 읽는 OCR은 현재 지원 담당자가 별도로 실행하는 시험 도구이며, 앱 설치본에 포함된 자동 기능은 아닙니다.

## 1. SRT가 있을 때

1. 새 프로젝트에서 **내 컴퓨터 파일 → 자막 파일로 시작**을 선택합니다.
2. 영상 파일을 고르고 **이 영상·음성을 사용할 권리가 있습니다.**를 확인합니다.
3. **프로젝트 만들고 자막 선택**을 누릅니다.
4. 가져오기 창에서 자료 출처와 문자 인코딩을 선택하고 **SRT 선택 및 미리보기**를 누릅니다.
5. 문장, 처음·마지막 시간, 오류·주의 항목을 확인합니다. 필요하면 아래 설명대로 시간차와 겹침을 해결합니다.
6. **새 초안 적용**을 누릅니다. 각 자막은 대사 행이 되며, 여러 줄 문장은 같은 행 안에서 유지됩니다. 영상의 시작·끝과 자막 사이에서 **2초 이상 비는 시간에는 해설 후보 행**이 함께 생깁니다. 미리보기에서 대사와 해설 후보의 개수를 따로 확인할 수 있습니다.

이 경로에는 API 키나 음성 분석 모델 다운로드가 필요하지 않습니다. 로컬 파일로 작업하며, 가져오기만으로 음성 분석이나 외부 전송을 시작하지 않습니다. 현재 입력은 로컬 영상 프로젝트와 **5 MB 이하 SRT**입니다. 다른 자막 형식은 SRT로 준비해 주세요.

기존 프로젝트에서는 **작업 도구 → 대사 초안 준비 → 자막 파일로 시작**으로 엽니다. 미리보기와 취소는 기존 대본을 바꾸지 않습니다. **새 초안 적용은 현재 대사·해설 전체를 새 대사와 해설 후보 초안으로 교체**하므로, 이미 작성한 해설을 이어 쓰려면 적용 전 내용을 확인하세요. 적용 직전 대본은 복구본으로 보관됩니다.

해설 후보에는 **‘※ 해설 후보 · 대사와 소리를 확인하세요’**라는 안내가 들어갑니다. 자막이 보이지 않는 시간에도 외국어 대사·음악·효과음이 있을 수 있습니다. 후보는 무음 판정이나 완성된 해설이 아니므로, 영상을 들으며 실제로 쓸 위치를 정하고 안내 문구를 해설로 바꾸세요.

이미 가져온 대본에 후보가 없다면 **작업 도구 → 빈 시간에 해설 후보 넣기**를 열고 같은 이름의 버튼을 누릅니다. 기존 대사와 작성한 해설을 보존하고, 아무 행도 차지하지 않는 2초 이상의 시간만 채웁니다. 반복해서 눌러도 기존 구간과 중복하지 않습니다. 로컬 영상의 길이를 확인한 프로젝트에서 사용할 수 있으며, 추가 전 대본은 복구본으로 보관됩니다.

## 2. SRT 없이 직접 시작하기

새 프로젝트에서 **대사를 직접 입력**을 선택하고 영상과 사용 권리를 확인한 뒤 **프로젝트 만들고 직접 입력**을 누릅니다. 열린 입력창에 시작 시간, 종료 시간, 대사 내용을 넣고 **행 추가**를 누릅니다. 기존 프로젝트의 **작업 도구 → 대사 초안 준비 → 대사를 직접 입력**에서도 사용할 수 있습니다.

시간 입력은 `분:초.밀리초` 형식입니다. 예를 들어 7.25초는 `00:07.250`, 1시간은 `60:00`입니다. **현재 영상 시간을 시작으로 / 현재 영상 시간을 종료로**를 누르면 재생 위치를 가져옵니다. 시작은 종료보다 빨라야 하며 영상 길이와 다른 행의 시간을 확인해야 합니다.

시간 없는 대본을 내용 칸에 붙여 넣을 수 있지만, 앱이 임의로 시간을 붙이지 않습니다. 시작·종료를 넣고 행을 추가해야 저장됩니다. 작성 중 다른 화면으로 이동할 때 입력이 남아 있다는 안내가 나오면 **행 추가**로 저장하거나 **취소**로 입력을 닫습니다.

## 3. 영상과 자막 시간 맞추기

가져오기 미리보기의 **전체 시간차 (ms)**는 모든 자막에 한 번 적용하는 시간 이동입니다. 양수는 늦게, 음수는 일찍 표시합니다.

| 필요한 이동 | 입력 |
|---|---:|
| 1.5초 늦추기 | `1500` |
| 0.25초 앞당기기 | `-250` |
| 1시간 앞당기기 | `-3600000` |

초반·중간·후반의 대사를 영상과 비교하세요. 초반만 맞고 뒤로 갈수록 어긋나면 일정한 시간차만으로 해결되지 않을 수 있습니다. 다른 편집본인지 확인하거나 구간별로 직접 수정합니다. 시간 이동으로 시작이 음수가 되거나 종료가 영상 밖으로 나가면 적용할 수 없습니다.

적용 후에는 **작업 도구 → 대사 시간 전체 맞추기**에서 **모든 대사 행 / 선택한 대사 1행**을 고르고 **시간차 (ms) → 대사 시간 이동**을 사용합니다. 버튼을 누를 때마다 현재 편집 시간에 값을 더하므로 같은 값을 반복 적용하지 않도록 확인합니다. 아직 내용·시간을 수정하거나 확인 완료하지 않은 자동 해설 후보는 바뀐 빈 시간에 맞춰 다시 배치합니다. 작성하거나 확인한 해설은 원래 위치에 남습니다. 이동한 대사가 기존 해설과 겹치거나 영상 범위를 벗어나면 적용되지 않습니다.

원본 자막의 시간은 별도로 보존됩니다. 문장이나 시간을 바꾸면 해당 행의 확인 완료 표시가 해제되므로 다시 대조해 주세요. 자막의 표시 시간과 외국어 음성의 발화 시간은 다를 수 있습니다.

## 4. 글자가 깨지거나 시간이 겹칠 때

**문자 인코딩:** 기본 자동 감지는 BOM이 있는 UTF-8·UTF-16을 확인하고, 그 외에는 UTF-8로 읽습니다. 한글이 깨지거나 읽기 오류가 나면 **UTF-8 / UTF-16 LE / UTF-16 BE / EUC-KR / CP949** 중 원본 형식에 맞는 항목을 선택합니다. 인코딩이나 출처를 변경했다면 **다른 SRT 선택 및 미리보기**로 같은 파일을 다시 선택해 반영합니다. 새 미리보기에서는 시간차와 겹침 선택도 다시 확인합니다.

SRT의 번호, `00:00:07,250 --> 00:00:10,500` 같은 시간 줄, 문장, 큐 사이의 빈 줄을 확인하세요. 형식 오류·빈 문장·잘못된 시간 범위는 원본 파일을 고친 뒤 다시 가져옵니다. 일부 굵게·기울임 등의 서식 태그는 일반 글자로 바뀌며 주의 항목에 표시됩니다.

**겹침:** 가져오기 창의 **겹치는 자막**에서 문장을 비교합니다. 두 자막을 같은 구간으로 묶어도 되는 경우에만 **이 그룹 합치기**를 누릅니다. 선택한 그룹의 시작 최솟값과 종료 최댓값으로 한 행을 만들고 연결된 원문을 보존합니다. 서로 다른 대사를 분리해야 한다면 원본 SRT의 시간을 고쳐 다시 가져옵니다. 겹침을 자동으로 삭제하거나 임의의 순서로 바꾸지 않습니다.

미리보기는 처음 50행까지 표시합니다. 화면에 보이는 부분이 전체 검수를 대신하지 않으므로 적용 후 나머지 행도 확인합니다. 미리보기 중 원본 영상·SRT·프로젝트가 바뀌거나 미리보기가 만료되었다는 안내가 나오면 다시 선택해 확인합니다.

## 5. 출처를 남기고 한 행씩 확인하기

가져오기 창의 **자료 출처**는 **제공받은 자막 / 영상에서 추출한 자막**, **처리 권한 기록**은 **확인되지 않음 / 영화제 제공 / 지원 담당자 제작** 중 사실에 맞게 선택합니다. 이 선택은 출처 기록이며 앱이 권리나 번역 정확도를 인증한다는 뜻이 아닙니다.

자막 원본 파일, 문장과 시간, 파일 식별값, 가져오기·시간차·합치기 기록은 프로젝트에 남습니다. 행을 선택하고 **작업 도구 → 선택한 행의 원문과 출처**에서 편집 내용과 비교할 수 있습니다. 편집한 행을 누르면 현재 시작 시간으로, 원문 영역의 시간을 누르면 원문에 연결된 위치로 이동합니다.

영상을 보며 내용·줄바꿈·문장부호·시작·종료를 고친 뒤 **확인 완료 · 다음**을 누릅니다. 단순히 편집하거나 다음 행으로 이동하는 것만으로 확인 완료가 되지는 않습니다. SRT가 영화제 제공본이거나 지원 담당자가 정리한 파일이어도 필요한 영상 대조는 별도로 수행합니다.

## 6. 저장·복구·내보내기

편집 후 **자동 저장됨**을 확인하고 **내 프로젝트**에서 다시 열어 이어 씁니다. 원본 영상은 복사되지 않으므로 기존 위치에 보관하세요.

잘못된 새 초안, 해설 후보 추가 또는 시간 이동을 적용했다면 **작업 도구 → 이전 상태로 복구 → 이전 저장 목록 보기**에서 작업 직전의 원하는 저장본을 선택하고 **선택한 저장본으로 복구**를 누릅니다. 주요 작업의 최근 10개 복구본을 유지하며 모든 타이핑 순간이나 원본 영상을 백업하는 기능은 아닙니다. 복구 직전 내용도 저장본으로 남습니다.

**대본 내보내기 → HWPX 내보내기**는 대사와 해설을, **SRT 내보내기**는 현재 대사 행만 저장합니다. 편집한 밀리초 시간과 문장을 사용하며, SRT에 해설 행은 포함하지 않습니다. 같은 이름이 있으면 새 버전 파일을 만듭니다. 시간·내용 오류는 먼저 고치고, 확인 전 행이 남은 작업용 출력은 최종 검수본과 구분합니다. HWPX는 한컴오피스에서 실제 페이지 나눔과 서식을 확인하세요.

## 지원 담당자용: 현재 OCR 도구와 실측 범위

현재 OCR은 앱 밖의 별도 지원 자료로 준비되어 있으며 저장소·설치본에 들어 있지 않습니다. 지원 자료 묶음의 `setup-ocr-models.py`, `extract-ocr-blind.py`, `evaluate-ocr-after-extraction.py`, `ocr-requirements.lock.txt`, `ocr-model-manifest.json`, `OCR_SPIKE_REPORT.md`를 이용합니다. 일반 작가는 검토한 SRT를 받아 앱에서 시작하면 됩니다. 이 문서만 내려받았을 때 위 파일이 없다는 이유로 앱 내부 파일을 찾을 필요는 없습니다.

2026-09-15에 [Sintel 공식 다운로드](https://durian.blender.org/download/)가 연결하는 영어 음성 영상과 [공식 한국어 SRT](https://download.blender.org/durian/subs/sintel_ko.srt)를 확보했습니다. [공식 영어 SRT](https://durian.blender.org/wp-content/content/subtitles/sintel_en.srt)와 26개 큐의 시간코드가 동일했습니다. 자료의 [CC BY 3.0 및 출처 표기 조건](https://durian.blender.org/sharing/)을 기록하고, 원본 100–190초 구간에 한국어 자막을 새로 합성해 90초 시험 영상을 만들었습니다.

시험은 Python 3.11.15, RapidOCR 3.9.2, ONNX Runtime 1.23.2, PyAV 18.0.0, PP-OCRv5 한국어 인식기로 수행했습니다. [RapidOCR 한국어 모델 지원표](https://rapidai.github.io/RapidOCRDocs/main/model_list/)와 [공식 모델 해시 목록](https://github.com/RapidAI/RapidOCR/blob/main/python/rapidocr/default_models.yaml)을 확인하고 모델을 로컬에 고정했습니다. 기본 중국어 인식기를 한국어 모델로 간주하지 않았습니다. [PaddleOCR 한국어 인식 모델 설명](https://www.paddleocr.ai/main/en/version3.x/module_usage/text_recognition.html)

영상만 입력받아 하단 35%를 고정 5 fps로 읽었고, [PyAV 프레임 PTS](https://pyav.basswood.io/docs/stable/api/frame.html)로 시각을 기록했습니다. SRT 정답은 추출 완료 후 별도 평가에서만 읽었습니다. CPU는 Ryzen 5 3500X이며 ONNX는 4개 연산 스레드를 사용했습니다.

| 첫 블라인드 시험의 90초 표본 결과 | 값 |
|---|---:|
| 실제 / 추출 큐 | 12 / 16개 |
| 시간 겹침 기준으로 검출한 실제 큐 | 12/12개 |
| 큐 정밀도 | 75% — 가짜 큐 4개 포함 |
| 매칭 큐 문자 오류율 | 2.03% — 공백 제외, 문장부호 포함 |
| 가짜 출력 글자도 포함한 문자 오류율 | 5.41% |
| 시작·종료 절대오차 중앙값 | 69 / 71 ms |
| 시작·종료 절대오차 95백분위 | 88 / 88.85 ms |
| 전체 처리 시간 | 40.60초 |

12개 큐의 매칭은 문구가 아닌 시간 겹침 비율 0.5 이상으로 1:1 대응시킨 결과입니다. 문자 오류에는 말줄임표 누락이, 가짜 큐에는 배경을 `-`, `7`, `2L`, `0`으로 읽은 경우가 있었습니다. 원래 측정 결과는 그대로 보존합니다.

별도의 `sintel-dialogue-90s-ocr-reference-assisted-reviewed.srt`는 **공식 정답을 참조한 시험 정리본**입니다. 가짜 큐 4개를 지우고 공백·말줄임표를 고쳤으며 OCR에서 추정한 시간은 유지했습니다. 독립적인 사람의 영화 전수 검수나 두 번째 블라인드 시험으로 표현하지 않습니다. 출처는 **영상에서 추출한 자막 / 지원 담당자 제작**으로 기록합니다.

이 표본은 한 글꼴로 새로 합성한 짧은 장면이며 실제 BIFF 영상이 아닙니다. 5 fps에서는 200 ms보다 짧은 자막을 놓칠 수 있고 경계는 관측 사이의 추정값입니다. 다른 배급본의 글꼴·압축·상단 자막·페이드·가변 프레임률과 장편 처리 성능을 검증하지 않았습니다. **개발자 OCR → 영상 대조와 수정 → SRT 제공** 방식으로 사용하고, 앱에 OCR을 직접 넣거나 장편 품질을 보장하기 전 실제 자료를 검증해야 합니다.

## 개발자용: 실제 Electron 자막 QA 재현

저장소의 `scripts/qa-subtitles.mjs`는 위 지원 자료의 **90초 영상 + 공식 시간의 12개 큐 SRT**를 사용합니다. 아래 두 파일을 저장소와 별도의 로컬 폴더에 준비하세요. 참조 정리본이나 26개 큐 전체 SRT로 대체하면 고정 시각 검사가 실패합니다.

| 파일 | SHA-256 |
|---|---|
| `sintel-dialogue-90s-ko-burned.mp4` | `faf36304bf8936f5723f1dab4845f814e17da85da2bbef7a3ef9dd18f36ba9c6` |
| `sintel-dialogue-90s-ko.srt` | `c7cff0f517eded19262dde7c5128884f00cffe2e2147866d1d2cc67d5575cac8` |

지원 자료의 `SOURCE_MANIFEST.md`에 영상·자막 URL, 라이선스, 전체/발췌 구간, 렌더링 방법이 있습니다. 전체 원본 100–190초 구간과 한국어 SRT의 시각에서 100초를 뺀 12개 큐로 만들어진 자료입니다. 저장소에는 영화나 OCR 모델을 포함하지 않습니다.

[개발 환경](../README.md#개발)에 따라 앱 의존성, 미디어 실행 파일과 HWPX 템플릿을 준비하고, Playwright를 사용할 수 있는 개발 환경에서 저장소 루트를 현재 폴더로 실행합니다.

```powershell
npm run build

# 준비한 90초 자료가 있는 실제 폴더로 바꿉니다.
$validationDir = (Resolve-Path '..\validation-media').Path
$env:GINUNI_QA_MEDIA = Join-Path $validationDir 'sintel-dialogue-90s-ko-burned.mp4'
$env:GINUNI_QA_SRT = Join-Path $validationDir 'sintel-dialogue-90s-ko.srt'

node scripts/qa-subtitles.mjs
```

두 환경 변수에는 실제 파일의 절대 경로를 지정합니다. 기본적으로 스크립트는 `import('playwright')`를 사용합니다. Playwright가 별도 개발 도구 폴더에 설치되어 있다면 선택적으로 해당 패키지의 `index.mjs`를 지정합니다.

```powershell
$qaToolsDir = (Resolve-Path '..\qa-tools').Path
$env:GINUNI_PLAYWRIGHT_MODULE = Join-Path $qaToolsDir 'node_modules\playwright\index.mjs'
node scripts/qa-subtitles.mjs
```

이 QA는 임시 프로젝트·설정 폴더와 대체 파일 선택 응답을 사용합니다. 음성 분석 서비스를 실행하거나 OpenAI API를 호출하지 않습니다. SRT 미리보기와 적용, 12개 행의 정확한 시간, 편집·확인·영상 이동·원문 보기, 전체/선택 시간 이동, 재열기, HWPX/SRT 출력, 시간을 직접 입력하는 첫 행과 미저장 입력 보호를 실제 Electron 화면을 통해 확인합니다. 초기 가져오기는 첫 시작 `7250 ms`, 마지막 종료 `55870 ms`를 기대합니다. 이후 시험에서 시간을 이동한 뒤 SRT 출력의 첫 시작이 `7350 ms`인지 확인합니다.

결과는 콘솔과 `output/playwright/subtitle-qa-result.json`에, 확인 화면은 같은 폴더의 `subtitle-preview.png`, `subtitle-review.png`에 남습니다. 실패 시 `subtitle-failure.png`와 `subtitle-failure.txt`를 남기며 임시 프로젝트·출력 폴더는 종료 때 정리합니다. 이 검사는 앱 동작 회귀 검사이며 OCR 정확도, 실제 작가 사용성, 한컴오피스 실제 렌더링 또는 BIFF 영화 검수를 대신하지 않습니다.
