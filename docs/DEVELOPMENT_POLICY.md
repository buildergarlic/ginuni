# 개발 운영 정책

## 기본 원칙

GiNuNi는 PR 화면 자체를 품질의 증거로 사용하지 않습니다. AI가 코드를 만들고, 같은 AI가 스크린샷을 첨부하고, 다시 AI가 승인하는 과정은 인간의 협업이나 합의를 대신하지 못합니다.

관리자와 AI 에이전트의 일상적인 변경은 다음 흐름으로 처리합니다.

1. 유일한 개발 원본 `C:\GiNuNi\screen-description-script-maker`에서 수정합니다.
2. 변경 범위를 확인하고 관련 테스트와 `npm run verify`를 로컬에서 실행합니다.
3. 검증된 변경만 작고 설명 가능한 커밋으로 남깁니다.
4. `main`에 직접 푸시합니다.
5. GitHub Actions의 `Code verification` 결과를 확인합니다.
6. 배포가 필요할 때만 버전과 변경 기록을 갱신하고 `v*` 태그를 푸시합니다.

## PR을 사용하는 경우

PR은 기본 개발 단계가 아닙니다. 다음처럼 사람이 실제로 읽고 판단하고 토론할 때만 사용합니다.

- 외부 기여자가 변경을 제안하는 경우
- 여러 인간 개발자가 설계 선택을 합의해야 하는 경우
- 소유자가 별도의 인간 리뷰를 명시적으로 요청한 경우

AI 에이전트끼리 형식적인 승인 기록을 만들기 위한 PR은 생성하지 않습니다. 이미 `main`에 반영된 브랜치를 다시 PR로 만들거나, 사람이 보지 않을 자동 스크린샷을 승인 증거처럼 첨부하지 않습니다.

## 검증의 의미

- 테스트, 타입 검사, 빌드는 재현 가능한 기계 검증입니다.
- 스크린샷은 사용자가 화면 결과를 판단할 필요가 있을 때만 보조 자료로 사용합니다.
- GitHub Actions 성공 표시는 사람의 코드 리뷰나 제품 승인과 같은 뜻이 아닙니다.
- UI, HWPX 렌더링, 실제 음성 분석처럼 자동 검사만으로 판단하기 어려운 항목은 릴리스 전에 사람이 직접 확인합니다.

## 안전장치

- `main` 강제 푸시와 삭제는 금지합니다.
- 모든 변경은 되돌릴 수 있는 일반 커밋으로 남깁니다.
- 앱 배포는 검증된 `v*` 태그에서만 생성합니다.
- API 키, 대사, 음성, 사용자 전체 경로는 커밋과 CI 로그에 넣지 않습니다.
- 의존성 보안 경고는 유지하되 자동 PR은 만들지 않습니다. 필요한 업데이트는 로컬 검증 후 직접 반영합니다.

공개 저장소의 기본 브랜치 보호는 외부 계정에 대해 유지합니다. 저장소 소유자와 명시적으로 허가된 관리자만 직접 푸시하고, 그 밖의 기여는 사람의 협업이 필요한 예외 PR 흐름을 사용합니다.
