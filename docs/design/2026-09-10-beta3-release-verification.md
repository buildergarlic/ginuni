# GiNuNi 0.6.0-beta.3 브랜딩·배포 검증

## 범위

사용자가 확정한 로고·아이콘의 흰 배경과 디자인을 그대로 사용한다. 앞서 승인·구현된 Balanced Atelier UI와 함께 기존 GiNuNi의 호환 업데이트로 배포한다. 앱 ID·제품명·바로가기 이름·프로젝트 저장 위치·프로젝트 스키마는 변경하지 않는다.

이는 자동 검사와 개발 환경 검증 기록이다. 실제 작가의 사용성 시험, 한컴오피스 실문서 표시, 깨끗한 Windows 설치·제거·업데이트 후 데이터 보존은 별도다.

## 원본 및 배치

| 사용자 제공 파일 | 앱에서 사용하는 위치 |
| --- | --- |
| ginuni-logo.png · 2172×724 | 시작 화면·About; renderer에 번들 |
| ginuni-icon.png · 1254×1254 | HTML 아이콘 및 런타임 브랜딩 리소스 |
| ginuni-app.ico · 16–256px | Windows 앱 창, EXE, NSIS 설치·제거 아이콘 |

PNG·ICO는 바이트 단위로 복사한다. 배경 제거·재색칠·크롭·재생성은 하지 않는다. CSS는 원본 전체를 비율대로 표시하며 흰 배경을 유지한다. 기존 디자인 시안과 다른 로고는 사용자가 승인한 후속 변경이다.

원본과 복사본에서 일치한 SHA-256:

```text

ginuni-icon.png  3e1b1a76133495b6edcde9603b2dfce5e02407ca5a276165418b928a0bc42849
ginuni-app.ico   23732b31cafa0f817798634e665ea4812d3374af670563c5a5eeb4e1d2fd7066
```

## 검증 방법

- `npm ci`와 `npm run verify`: 잠금 파일 기반 의존성, 타입, 단위 테스트, 제품 빌드.
- `qa-branding.mjs`: 실제 Electron에서 원본과 로드된 이미지 해시, 이미지 크기·비율·흰 배경, 창 아이콘 호출과 1440/800px 화면.
- `qa-atelier.mjs`, `qa-workflow.mjs`, `qa-guide.mjs`, `qa-youtube-seek.mjs` 및 `--live`: 분리된 프로필에서 저장·검수·복구·출력·긴 대본·사용법·영상 이동.
- `qa-packaged-branding.mjs`: 앱 EXE와 설치 EXE의 실제 PE 아이콘 리소스가 제공된 ICO의 모든 프레임과 바이트 단위로 같은지 검사. 설정 문자열만 확인하는 검사가 아니다.
- 배포 후 GitHub Actions, 자산과 체크섬, 실제 서명 상태를 확인한다.
- `scripts/qa/release-update-boot.cjs`: 이전 버전 어댑터와 격리 캐시에서 실제 NSIS updater의 새 버전 발견·다운로드를 확인한다. 설치·재시작은 금지하며, 설치된 기존 앱의 데이터 이전 검사를 대신하지 않는다.

아이콘 검사 부정 대조: 변경 전 beta.2 설치 EXE는 새 로고 프레임 불일치로 실패했다. 브랜딩 적용 전 렌더러·창 아이콘 검사도 누락을 검출했다.

| 로컬 설치 EXE·앱 EXE의 Authenticode | 모두 `NotSigned` |
| 배포 검사용 updater 사전 점검 | beta.1 어댑터 → 실제 게시된 beta.2 발견·다운로드 통과; 설치하지 않음 |

앱 시나리오는 총 41개를 통과했다. 렌더러 미처리 오류는 없었다. 유튜브 실제 영상 검사는 공개 IFrame API 예제 `M7lc1UVf-VE`로 했으며 다운로드나 유료 AI 호출은 하지 않았다. 원격 게시 결과는 GitHub의 해당 태그와 Actions 실행 기록으로 확인한다.

검수 이미지와 상세 테스트 프로필은 Git에 넣지 않는 `output/playwright` 아래에 보관했다. 의존성 설치가 끝나기 전에 시작한 한 번의 타입 검사는 모듈 미설치 상태로 실패했으며, 설치 완료 후 전체 검사를 새로 실행해 위 결과를 얻었다.

로컬 설치 파일 SHA-256은 `b80482c5abad26e3c605a49d225c78c75f0307840d0b58ee58ba6d9dabae57fb`이다. GitHub Actions는 별도로 빌드하므로 **공개 다운로드 검증에는 Releases에 게시된 SHA256SUMS.txt를 사용**한다. 게시 뒤에는 beta.2 어댑터에서 새 beta.3을 실제로 찾고 내려받는지 별도로 점검한다. 이 태그 전 기록은 원격 게시·업데이트 설치를 통과했다고 주장하지 않는다.
